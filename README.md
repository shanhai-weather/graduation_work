## 1. サービス概要

- アプリ名：ほめほめ日記

- このサービスはどんなサービスか
日常生活や仕事の中で頑張ったこと、誰かのために行動したことなどを記録し、定期的に振り返ることで、自分自身の強みを発見するためのサービス。
普段は当たり前だと思っている小さな行動や努力から、自分の良さを理解し、言葉にすることをサポートする。

- 誰の、どんな課題を、どう解決するか
転職活動に向けて自己分析を始めたものの、自分の強みや長所が分からず、うまく言葉にできない25歳〜29歳の若手社会人を対象とする。
日常生活や仕事の中にある小さな行動や努力、他者への思いやりなどを気軽に記録し、定期的に振り返ることで、自分では当たり前だと思っていた行動の中から強みを発見し、自分の言葉で表現できるようにする。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

転職活動に向けて自己分析を行った際、自分の強みや長所をうまく見つけられなかったこと。
自分の強みを考えたときに、なかなか思いつかず、過去の経験を振り返っても、何が強みなのか悩み、すぐには強みを言語化できなかった。
自己分析がうまくいかず、自分には強みがないのではないかという不安や、自分自身のことを十分に理解できていないもどかしさを感じた。
一方で、日常生活の中で自然とできていることや、普段から意識が向いていること、誰かのために行うちょっとした優しい行動などに、その人の強みが表れているのではないかと考えるようになり、日々のちょっとした頑張りを記録することが強み発見につながると感じた。

---

### 2-2. なぜそれが「気になった」のか

自分自身の強みを見つけられなかった経験を通じて、強みは成果や特別な経験など、分かりやすい実績だけから見つけるものではないと感じたから。
日常生活の中には、本人にとっては当たり前になっている行動や、無意識に行っている気配り、誰かを思いやる行動などが数多くある。しかし、そのような行動は意識して振り返る機会がなければ、自分の強みとして認識されないまま見過ごされてしまう。
こうした何気ない行動や小さな努力を積み重ねて振り返ることが、自分自身の特徴や強みを理解することにつながると考えられる。
自分と同じように強みをうまく言葉にできずに悩んでいる人が、日常の中にある自分の良さに気づき、自分自身が納得し、自信を持てる「強み」を発見するきっかけを提供したいと思い、このアプリを考えた。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

自己分析をしたとき、自分の強みや長所をうまく言葉にできないこと。
過去の経験から強みにつながる要素を見つけることが難しく、自分の良さや得意なことが挙げられない。
転職活動での面接などで、自分の強みを自信を持って答えることが難しい。

---

### 3-2. 本当に解決したい課題は何か

自分の強みにつながる経験や行動を、十分に把握できていない。過去の大きな出来事や成果ばかりを振り返り、日常生活の中にある小さな行動や努力を見落としてしまいがち。
日常の何気ない行動や小さな努力は、自分にとって当たり前になっており、強みとして意識する機会が少ない。また、日々の出来事は時間が経つと忘れてしまい、記憶に残らない。
自分の行動や良さを客観的に振り返り、自分自身の特徴として捉える習慣や機会が少ない。その結果、自分ではできていることや大切にしていることがあっても、それを自分の強みとして把握できない。

→本当に解決したい課題：
日常生活の中にある自分の何気ない行動や小さな努力を振り返る機会が少なく、自分自身の「強み」に気づけていないこと。その結果、自分の強みを理解して言語化することが難しく、転職活動などで自己分析を行った際に、自分には強みがないのではないかと感じ、自信を持てなくなることがある。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢設定：
  - 年齢：25歳～29歳(第二新卒を含む若手社会人)
  - 理由：自分のキャリアや今後の働き方について見直す機会が増え、転職も視野に入れることが多い年代。これまでの経験を振り返り、自分の強みや長所を整理する必要がある一方で、まだ仕事で大きな成果がない場合も多く、自分の強みを見つけにくいと感じる人もいるため。

生活・状況設定：
  - 生活・状況：現在働いている会社からの転職を考えており、自己分析を始めている。自分の強みや長所を整理しようとしているが、過去の経験を振り返っても、何を強みとして伝えればよいのか分からず悩んでいる。
  - 理由：アプリを使うことで、日常生活や仕事の中で自然とできていること、小さな努力や他者への気配りなどを記録し、定期的に振り返り、自分では当たり前だと思っていた行動から強みを発見できるようにする。

環境設定：
  - 環境：仕事で目立った成果や実績を挙げられておらず、何が自分の強みなのか分からない。仕事の疲れもある中、強みを考えても思いつかず、自己分析の手が止まってしまう。自分の行動を振り返る習慣がなく、日々の出来事も時間が経つと忘れてしまう。
  - 理由：日常のちょっとした行動や努力を短い文章で気軽に記録できる仕組みを用意する。まとまった時間を取らなくても記録でき、定期的な振り返りによって過去の記録を自己分析に活用できるようにする。

## 8. このアプリの懸念点とその対策

### 懸念点

- 何が問題になりそうか：
日々の記録が面倒になり、アプリの利用が続かなくなる可能性がある。

- なぜそう思うか：
仕事や日常生活で忙しい中、毎日記録する時間を確保することが難しい場合がある。
また、何を記録すればよいか分からず、記録すること自体が負担になる可能性もある。

- そのために考えている対策：
記録項目をタイトル・内容・日付・カテゴリーに絞り、短い文章でも気軽に記録できるようにする。
また、特別な成果だけでなく、日常の小さな行動や他者への思いやりも記録の対象として伝え、気軽に利用できるようにする。

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| Ruby on Rails | 採用 | RUNTEQで学習しており、既存の知識を活用して開発できるため |
| Laravel | 不採用 | PHPの学習が新たに必要となり、開発に時間がかかるため |
| React・Next.js | 不採用 | フロントエンドとバックエンドを分ける必要があり、学習や実装の負担が増えるため |
| PostgreSQL | 採用 | 使用経験があり、Railsとの連携もしやすいため |
| MySQL | 不採用 | PostgreSQLの使用経験があるため、新たに変更する必要性が低いため |
| Render | 採用 | Railsアプリをデプロイでき、無料プランで開発・公開を試せるため |
| Neon | 採用 | PostgreSQLを無料プランで利用でき、Renderと組み合わせて使用できるため |

- 今回チャレンジしたい点
Railsでのモデル間の関連付けやデータの集計処理
ユーザーごとに記録を管理する機能の実装
RenderとNeonを利用したアプリのデプロイ

- 不安な点
本番環境と開発環境の設定の違い
デプロイ時のエラーやデータベース接続の設定
ユーザー認証やモデル間の関連付けを正しく実装できるか

### 10-3.キャッチアップ不足の懸念
今回の卒業制作では、できるだけRUNTEQで学習した技術を活用し、新しい技術の習得にかかる時間を抑える方針とする。
ReactやNext.jsなどの新しい技術は、MVPでは採用せず、まずはRailsだけでアプリを完成させることを優先する。
本リリース後に、必要性や実装の難易度を確認したうえで、Reactなどの導入を検討する。
また、実装を小さな機能単位に分け、分からない部分は調査や動作確認を行いながら進めることで、完成までのハードルを下げる。
まずはアプリとして完成させることを第一に考え、必要な情報を調べながら段階的に実装を進める。
